## 项目一：垂直行业资讯 AI 工作流平台（低空经济情报 · 微信公众号自动化）

**时间**：2025.08 – 至今（个人主导 / 由真实业务场景驱动）

### 问题与方案

**背景痛点**：垂直行业公众号需跟踪 20+ 媒体源；同一事件常有多篇报道（快讯 / 深度 / 数据不一致），编辑需反复检索、逐篇打开、人工拼稿；发前需核对出处与数字。初期「单篇抓取 + 摘要 + 草稿」无法解决同题分散与溯源问题。

**版本演进**（仓库真实分支，非虚构 V1/V2 目录）：

| 阶段 | 分支 / 基线 | 方案要点 |
|------|-------------|----------|
| **早期** | `main` | 单篇级流水线：RSS/抓取 → 摘要 → 微信公众号草稿箱 |
| **V3** | `v3-intelligence` / `V3/` | **事件优先**：去重 + **bge-m3** 向量聚类；多源 **AI 通稿** + 独立 **QA/Rewrite**；Prompt 外置；FastAPI BFF + 运营平台 |
| **V3.1** | 当前推荐分支 | **发布与运营**：importance **Top3**、**3 日**推送冷却、通稿 **≥800 字**门槛；平台一键 `run-once`；中文源 `published_at` 修复；GDELT 限速缓存；通稿 **〔n〕** 溯源 UI；BFF E2E **24/24** |
| **V4**（可选写简历） | `V4/` | Event Graph Memory（实体/关系/时间线），与口播/demo 无关可省略 |

### 独立负责

- **需求与方案**：从编辑 SOP（检索–比对–拼稿–发布）拆解为可执行 workflow，明确每阶段输入/输出与失败策略  
- **后端流水线**：Python `pipeline.run_once`（检索 → 预过滤 → 正文抽取 → 聚类/累增 → 事件扩搜 → 通稿 → QA → 发布规则）  
- **AI 层**：事件通稿 / 簇摘要 / QA-Rewrite 三套 Prompt 设计与迭代；中英文扩搜路由（中文栏目页 + 英文 GDELT/RSS）  
- **平台层**：BFF API、事件列表/详情/QA 页、重要性排序与「可推送」标签  
- **质量保障**：pytest 单测 + 冒烟脚本 + 前端 E2E；验收文档与演示口播/录屏稿件  

### 量化成果

| 类别 | 结果 |
|------|------|
| **数据源** | 配置 **20+** 媒体源（RSS + 中文栏目页监控 + GDELT 主题检索） |
| **聚类与去重** | 本地 **bge-m3** 向量聚类；同题 **累增** 至已有 Event，避免重复建事件 |
| **生成质量** | 事件级通稿 + 段落 **〔n〕** 溯源；通稿可见字数 **≥800** 否则跳过发布；QA **≥70** 分方可进可推送 |
| **发布策略** | 重要性 **Top3** 优先；同 topic **3 日冷却**；日配额按 **事件数** 去重计数 |
| **可测试** | BFF **24/24** API E2E；Browser 点击验收（事件详情/〔n〕/QA 重写记录/配置页） |
| **工程化** | Prompt 与代码分离；业务规则（时效窗、稿数上限、战争/离题拦截）配置化，改规则不改模型调用链 |

### 后续开发

- **V4 Event Graph Memory**：事件实体/关系/时间线（PostgreSQL + 图谱快照），支撑「政策–公司–事件」长期跟踪  
- **多垂直场景复制**：抽象行业词表与数据源模板，复用同一 workflow 骨架
