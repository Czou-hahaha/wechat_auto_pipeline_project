# V3.1 更新说明（相对 V3 / `v3-intelligence`）

> 分支：`V3.1`  
> 基线：仓库 `main` 上已发布的 V3 事件情报流水线（commit `2052eb4` 一带，远程 `origin/v3-intelligence`）  
> 发布提交：`992305e`（2026-05）

## 为什么要出 V3.1？

V3 已打通「检索 → 聚类 → 扩搜 → 通稿 → QA → BFF/平台展示」的主链路，但在**生产发布**、**运营配置**和**中文源质量**上仍有几处缺口：

1. **成本与质量**：对所有事件簇都做 DeepSeek 摘要，费用高、且弱相关稿也会进模型。
2. **重复推送**：同一话题在数天内可能被多次推送到公众号草稿箱。
3. **运营闭环**：改定时、改时间窗、触发 `run-once` 仍依赖 SSH/CLI，平台与 BFF 未统一。
4. **中文落地页**：多家中文 HTML 源 `published_at` 不稳，影响时间窗过滤与排序。
5. **GDELT 稳定性**：429、空响应、中英文混查导致扩搜与检索不稳定。

V3.1 在上述痛点上做了**可配置、可验收、可从前端操作**的一轮收敛，目标是把「每日只推最重要的几篇、且能复现验收」变成默认行为。

## 与 V3 对比：能力一览

| 领域 | V3（基线） | V3.1 |
|------|------------|------|
| **摘要范围** | 按 `MAX_PUBLISH_PER_RUN` 等上限处理多簇 | 默认仅对 **importance Top N**（`WECHAT_PUBLISH_TOP_N=3`）做摘要 + 可选推微信 |
| **推送去重** | 主要依赖去重/聚类 | 增加 **冷却期**（`WECHAT_PUBLISH_COOLDOWN_DAYS=3`）：同 `topic_key`/标题指纹近期已推则跳过 |
| **摘要质量门** | QA 分数门禁 | 增加 **可见字数下限**（`CLUSTER_SUMMARY_MIN_CHARS=800`），不足直接 `skipped_too_short` |
| **检索预过滤** | 抓取后过滤为主 | 增加 **无 LLM 主题预过滤**（`topic_prefilter`），GDELT/RSS 命中在抓正文前丢弃弱相关 |
| **importance 打分** | 扩搜模块内有 scoring | 流水线侧统一 **`cluster_importance`**，与 `event_enhancement.scoring` 对齐，供选簇与平台排序 |
| **定时调度** | `.env` 固定早晚点 | **`config/schedule_jobs.json`** + 平台可增删改；BFF 保存配置后 **自动拉起/停止 `run-scheduler`** |
| **手动采集** | 仅 CLI `run-once` | BFF **`POST/GET /api/pipeline/run-once|status`**；Platform 顶栏/Dashboard **「开始采集」** |
| **事件详情** | 通稿 + 关联稿列表 | **参考稿**分区（扩充+聚类合并滚动列表）、溯源主稿、通稿内 `〔n〕` 与草稿 **digest 剥离** |
| **草稿推送** | `draft/add` | 推送成功后可选 **清空 `extracted_text`**（`STRIP_EXTRACTED_TEXT_AFTER_WECHAT_DRAFT`）减体积 |
| **中文 HTML 源** | 部分站点时间解析弱 | 多站 **`published_at_css`**、pipeline 日期格式增强、检索结果 **落地页 backfill** |
| **GDELT** | 单客户端逻辑 | **`http_core`** 重试/缓存/串行节流；主题级 **仅英文串行**；扩搜 **语言路由**（`lang_detect`） |
| **Prompt** | 分散模板 | 新增 **`summary_editorial_rules.md`**；簇摘要强调高亮、国内参照、禁止元叙述 |
| **测试与验收** | 基础单测 | Top3 选簇、预过滤、调度、pipeline API、summary HTML 等 **20+ 新测**；**`全流程验收步骤_重要性Top3发布.md`** |

## 核心更新点（按模块）

### 1. 发布策略：重要性 Top3 + 冷却 + 字数门

**动机**：公众号日更只需少量高质量稿；全簇摘要浪费 token，且易推重复话题。

**行为**：

- `run-once` 聚类后按 `cluster_importance` 排序，只对前 `WECHAT_PUBLISH_TOP_N` 个簇调用 DeepSeek 摘要（默认 3）。
- 查历史 `articles.json`：若同 topic/标题在 `WECHAT_PUBLISH_COOLDOWN_DAYS` 内已有 `wechat_draft_pushed_at`，跳过。
- 摘要 HTML 去标签后不足 `CLUSTER_SUMMARY_MIN_CHARS`（默认 800）→ `skipped_too_short`，不进入发布。

**相关代码**：`src/pipeline.py`、`src/utils/cluster_importance.py`、`src/config.py`  
**验收文档**：`docs/全流程验收步骤_重要性Top3发布.md`

### 2. 检索链路：预过滤 + 中文时间 + GDELT 稳态

**动机**：减少无效抓取与 429；让 `MAX_ARTICLE_AGE_HOURS` 对中文源可靠生效。

**行为**：

- `topic_prefilter`：标题+摘要命中主题词才进入正文抓取（无额外 LLM）。
- `data_sources.json`：36kr、钛媒体、虎嗅等补充 `published_at_css`；pipeline 支持更多日期文本格式。
- `search_published_at_backfill`：检索命中缺时间时抓落地页补全。
- GDELT：`gdelt/http_core.py` 统一超时/重试/磁盘缓存；`GDELT_MIN_INTERVAL_SEC` 等降 429；扩搜按语言分流。

### 3. BFF 与 Platform：可运营的「采集控制台」

**动机**：产品/运营无需记命令即可改配置、看进度、触发一轮采集。

**新增/增强**：

| 能力 | 入口 |
|------|------|
| 后台 `run-once` | `POST /api/pipeline/run-once`，`GET /api/pipeline/status` |
| 定时任务 CRUD | `schedule_jobs.json` + `schedule_config` API |
| 调度进程管理 | `scheduler_run`：保存配置后 sync 子进程；BFF 启动时自动拉起 |
| 事件搜索/映射 | `event_search.py`、`enhancement_loader.py` |
| 通稿/推草稿 | `GET .../press`、`POST .../push-draft` |
| 平台 UI | 设置页表格化数据源、Pipeline 面板、事件详情参考稿区、`importance_score` 展示 |

### 4. 内容与 Prompt

**动机**：成稿更符合公众号阅读习惯，且避免编辑说明泄漏进正文。

**变更**：

- `docs/prompts/summary_editorial_rules.md`：高亮、国内参照、时间轴、禁止「口径不一致」类元叙述。
- `cluster_summary_user.md`、`news_single_summary.md` 等与上述规则对齐。
- `summary_html.py`：成稿 HTML 处理；推微信时 digest 剥离 `〔n〕`/`【n】` 引用标记。

### 5. 存储与微信

- 草稿推送成功后可清空正文缓存（`storage.clear_extracted_text_for_event`）。
- `wechat_draft.py` 集中草稿相关 BFF 逻辑；`push-today-drafts` 仍可补推失败轮次。

### 6. `event_enhancement` 子包（仓库根目录）

与 V3 共用扩搜配置，V3.1 同步升级：

- `gdelt/http_core.py`、`lang_detect.py`
- `expansion_cascade` / `expansion.yaml`：语言路由、并发与重试参数可调

## 配置与文件变更（升级时注意）

### 新增或强依赖的配置文件

- `V3/config/schedule_jobs.json` — 定时任务列表（可由平台写入）
- `V3/docs/全流程验收步骤_重要性Top3发布.md` — 端到端验收
- `V3/docs/prompts/summary_editorial_rules.md` — 摘要体例

### 建议在 `.env` 中确认的新增/默认值

```bash
WECHAT_PUBLISH_TOP_N=3
WECHAT_PUBLISH_COOLDOWN_DAYS=3
CLUSTER_SUMMARY_MIN_CHARS=800
RUN_ONCE_PUSH_TO_WECHAT=false          # 验收通过后再 true
STRIP_EXTRACTED_TEXT_AFTER_WECHAT_DRAFT=true
SEARCH_PREFILTER_ENABLED=true
GDELT_MIN_INTERVAL_SEC=5
GDELT_CACHE_TTL_MIN=30
```

完整列表见 `V3/.env.example`。

### 未纳入 Git 的运行时数据（与 V3 相同）

- `V3/.env`、本地 `data/articles.json` 等（`.gitignore`）
- 验收日志、备份目录、`data/cache/gdelt/` — 仅在本地保留

## 已知限制（V3.1 未解决）

- 微信公众号 **IP 白名单**（`40164`）仍需在公众平台配置，否则 `RUN_ONCE_PUSH_TO_WECHAT=true` 整轮不推送。
- 向量聚类默认仍可由 `EMBEDDING_CLUSTER_ENABLED` 关闭；Top3 选簇在 topic 聚类与向量聚类下均生效，但 importance 分数依赖稿源与关键词配置质量。
- 部分集成脚本（`tests/integration/run_zh_*`）需在**本机终端**执行，CI/沙箱可能无法访问外网。
